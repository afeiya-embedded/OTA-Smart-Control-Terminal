# 2026-10-09

## 排查：app1.1 上电后 MQTT 连上了但数据不上传

现象（串口助手 COM17 / 115200 抓 ML307R 日志）：
```
ML307R-DC-RTU V4.34
SIM:READY
REGISTER:SUCCESS
MQTT_CONNECT:xthings.cloud:1883
MQTT 服务器连接失败      <- 被按 GBK 解码成乱码，实为 UTF-8 中文
```

结论：模组侧 MQTT 连接 Broker 失败，所以 STM32 每 5s 发的 `MQPUB,...` 没有会话可发，
服务器自然收不到遥测数据。

定位到的问题：
1. 串口助手用 GBK 解码模组输出的 UTF-8 中文 -> 乱码，掩盖了真实错误原因。
2. `wifi4g.c: WIFI4G_Parse_Queue()` 只识别 ASCII `ERROR\r\n`，不识别模组的中文
   "服务器连接失败"，因此 STM32 永远拿不到失败状态。
3. `mqtt.c: MQTT_Connect_Server()` 用子串 "MQTT_CONNECT:" 判成功，而模组打印的
   "MQTT_CONNECT:host:port" 只是连接目标，不是成功确认 -> 会误报 OK。
4. `mqtt.c: MQTT_SendData()` 拼的 payload `{TP:%d,RH:%d,...}` 键名没加引号，
   不是合法 JSON，ThingsBoard 会拒绝。
5. app1.1 只发 AT+MQMULTEN / AT+MQTTFILTER / AT+MQSUBM×3 / AT+REST，
   没有下发 AT+MQTTIP / AT+MQTT / AT+MQPUB，服务器地址与凭据完全依赖模组 flash 里
   的旧配置。

文件：Core/Src/mqtt.c、Core/Src/wifi4g.c、Core/Src/main.c

## 已实施的补丁（app1.1，git 工作区，未提交）

1. `Core/Src/mqtt.c` `MQTT_SendData()`：遥测 JSON 键名补双引号
   `{TP:%d,...}` -> `{\"TP\":%d,...}`。
2. `Core/Src/wifi4g.c` `WIFI4G_Parse_Queue()`：在 Parse_Substr 判断之前，
   优先匹配 UTF-8 字节 `"\xE6\x9C\x8D\xE5\x8A\xA1\xE5\x99\xA8"`（"服务器"），
   命中即返回 WIFI4G_ERROR。
3. `Core/Src/mqtt.c` `MQTT_Connect_Server()`：收到 "MQTT_CONNECT:" 后
   再观察 1 秒，若期间收到失败提示则返回 RESET，不再误报 OK。

校验：括号配对检查通过；`git diff --stat` = 24 insertions / 1 deletion。

## 踩坑记录（重要）

- 该工程源文件在磁盘上是 **CRLF + Tab 缩进**（仓库内是 LF）。
  用 Edit 工具改 `mqtt.c` 时整个文件被重写、每行少了一个 Tab，
  产生了 734 行的噪声 diff。回退后改用 Python 按字节精确替换才干净。
  → 以后改这个工程的源文件，优先用字节级替换脚本，并检查
  `git diff --stat` 是否最小化。
- 串口助手 UartAssist 默认 GBK 解码，读 ML307R 的 UTF-8 中文日志必然乱码。
  还原方法：`garbled.encode('gbk').decode('utf-8')`。
